# 统一数据契约 ·《团队工作台对接规范》v1

> 平台侧唯一数据口径。任何数据源接入（Git / 钉钉 / 团队工作台 API / 标准模板导出）
> 都必须产出本契约定义的**统一字段**，否则不允许进入平台业务库。
> 依据：`plan-ai-master.md` §4.2。脱敏要求见 `plan-ai-m1-data-masking.md`。

## 1. 为什么要有契约

- 各团队工具不一（Teambition / 禅道 / Excel / 自研系统），点对点硬编码会失控；
- adapter 一律加在**平台这一侧**，团队零改动；
- 团队接入成本 = 填一张契约表（§7）+ 提供一种数据出口（§5 三选一）。

## 2. 统一字段（唯一版本）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `task_id` | string | 是 | 来源系统任务号（如 TB 任务 id / 禅道 bug id） |
| `external_system` | string | 是 | 来源标识：`tb` / `git` / `dingtalk` / `workbench` / `template` |
| `title` | string | 是 | 任务标题 |
| `status` | string | 是 | 来源系统原始状态（原样保留，不翻译） |
| `status_category` | string | 是 | 归一化：`todo` / `doing` / `done`（平台只看这个做统计） |
| `assignee` | string | 是 | 负责人工号（**脱敏：展示层打码为工号，AI 层只留角色**） |
| `reporter` | string | 否 | 创建人工号 |
| `project_id` | string | 是 | 所属项目/产品线 |
| `iteration_id` | string | 否 | 所属迭代（无迭代可不填） |
| `start` | date | 否 | 计划开始 `YYYY-MM-DD` |
| `due` | date | 否 | 计划截止 `YYYY-MM-DD`（静默告警依赖） |
| `actual_end` | date | 否 | 实际完成日 |
| `progress` | number | 否 | 0-100 整数（**只作为佐证，不覆盖手写完成度**） |
| `story_points` | number | 否 | 故事点 |
| `workload` | number | 否 | 工时（小时）。**脱敏 L2：绝对值不流出平台，喂 AI 前转百分比** |
| `updated_at` | datetime | 是 | 数据更新时间（来源系统为准，对账用） |

## 3. adapter 接口约定

每个来源一个 adapter，统一形态：

```
采集（定时/事件） → 标准化（映射到 §2 字段） → 落库（平台业务库） → 对账（每日全量对比）
```

- 落库必须走平台 API（带乐观锁），禁止直接写数据文件；
- 全量对账以 `updated_at` 为准，来源系统最新者胜；
- adapter 运行必须写审计日志（`audit_log`，module = 来源标识）。

## 4. 数据分级（简表，完整见脱敏规范）

| 级别 | 范围 | 处理 |
|---|---|---|
| L1 | 任务标题、项目名、状态 | 平台内正常展示 |
| L2 | 工时、进度、偏差 | 仅内网；姓名→工号/角色 |
| L3 | 代码仓库内容 | **不进云端 AI**；只取统计特征（PR 数/合并率/评审耗时） |

## 5. 对接方式（三选一）

1. **API adapter**：团队系统提供只读 API（或 Webhook 推送），平台侧写 adapter。
2. **标准模板导出**：团队定期导出 CSV/Excel，平台侧定时导入（最简单，零开发）。
3. **Git 仓库**：平台直接采集 Git 仓库提交/PR（见 `plan-ai-m2-tasks.md` A2）。

## 6. 标准模板（方式 2 用）

文件：`任务数据模板.csv`（UTF-8，首行表头，列名与 §2 一致）。
校验规则（导入时逐行检查，失败行进 `import_errors` 日志不静默丢弃）：

| 规则 | 说明 |
|---|---|
| `task_id` 非空且行内唯一 | 空/重复 → 该行拒绝 |
| `status_category` ∈ {todo, doing, done} | 其他值 → 按映射表尝试转换，转不了拒绝 |
| `assignee` 非空 | 平台侧映射统一工号，查不到 → 拒绝并提示 |
| `due` 格式 `YYYY-MM-DD` | 非法 → 拒绝 |
| `progress` 0-100 整数 | 越界 → 拒绝 |
| `updated_at` 非空 | 缺失 → 拒绝 |

## 7. 接入步骤（团队侧 5 步）

1. 填表：明确 `external_system` 标识 + 字段映射关系（来源字段 → §2 字段）；
2. 选出口：§5 三选一（推荐模板导出起步）；
3. 试跑：提供 7 天历史数据，平台侧导入并对账（差异率 < 5% 视为通过）；
4. 上线：定时采集/推送接入；
5. 对账：每日自动全量对比，连续 3 天无差异后转人工抽查。

## 8. 变更管理

- 契约字段变更 = 文档升级版本 + 全 adapter 同步升级 + 存量数据迁移；
- 新增字段默认**从严**（先按 L2 处理，再按脱敏规范 §4.1 流程降级）；
- 本文件 v1 冻结期 30 天，期间只增不改删。
