## ✅ 已实现（2026-09-08，最终定稿）

> 口径调整：用户明确「项目总览 = 固定 8 阶段，与需求清单解耦」，且不要弹窗、要独立页面。故本功能已从"WBS 弹窗拆解"**重做为「项目总览」独立 Tab**。

**「项目总览」= 详情页的一个独立 Tab（📋）**，固定 8 阶段的项目级大纲，与 WBS 任务是**两套独立数据**：

- **数据**：`plan.overview[]`（独立于 `plan.tasks[]`），后端 `routes.js` 已加弱校验。
- **8 阶段（固定，不依赖需求清单）**：需求传递 / 环境准备 / 方案设计 / 技术详设设计 / 研发计划 / 测试计划 / 实证 / 上市交付。
- **交互（完整二级页面增删改查，非弹窗）**：
  - 空态：一键「初始化标准 8 阶段」；
  - 只读态：表格展示（阶段名/负责人/起止/状态/进度/交付物/备注）；
  - 编辑态：行内增删改每个阶段 + 「添加阶段」+「重置为标准 8 阶段」+ 保存/取消；
  - 新建计划时自动 seed 8 阶段；保存走现有乐观锁+校验链路。
- **需求清单已从总览移除**：粘贴/上传解析、按需求逐条展开等逻辑**已删除**，改为归入未来的「详细计划」（见下）。测试计划的 6 条子流程口径保留，将来在详细计划或总览增强里复用。

### ⏳ 详细 WBS 计划（暂缓，待用户想清楚）
用户意见：详细 WBS 不按阶段，而是**直接参考需求清单拆任务**，先保持现状。

## 1. 用户诉求（复述确认）

- 现状痛点：新建计划时 WBS 任务只能一条一条手动新增，很不便捷。
- 期望：上传/粘贴一份**较完整清晰的产品需求清单**，系统理解后自动拆解成一版 WBS 计划。
- 拆解链路（标准研发流程，用户明确指定）：
  ```
  需求传递 → 环境准备 → 方案设计 → 技术详设设计 → 测试方案设计
        → 研发计划（按需求清单逐条罗列）→ 系统测试 → 实证 → 上市交付
  ```
- 两种粒度（用户明确要二选一/都可）：
  1. **项目总览计划**：以上 9 个阶段作为一级任务，做一版粗粒度总览。
  2. **详细项目计划**：在总览基础上，把**「研发计划」阶段按需求清单每一条**展开成二级子任务；其余阶段保留一级或给默认子任务。
- 生成的是「一版初稿」，用户可在现有表单里继续编辑后再保存（不直接落库）。

## 2. 关键设计决策（需你拍板）

### 决策 A：用不用真·AI 模型？
本平台的一贯原则是**「本地规则先行 + 预留 AI 入口」**（见 plan 模块 AI 规则 Tab、handoff 文档）。据此给两个选项：

- **方案 A1（推荐先做）——纯本地规则解析，零依赖、零外部调用、零密钥**
  - 用户粘贴/上传需求清单（每行一条需求，或带简单编号/标题）。
  - 前端按规则解析：每一行=一条需求；再套用固定的 9 阶段模板生成任务树。
  - 「研发计划」阶段下，为每条需求各生成一个子任务（可带默认人天/负责人占位）。
  - 完全可控、即时、可离线，符合平台「不引入 Python / 不接外部 AI」的既有约束。
  - 命名沿用 plan 模块口径叫「智能拆解（规则）」，与 AI Tab 一致。

- **方案 A2（二期，接公司可控模型）——真·AI 拆解**
  - 预留 `aiConfig`（plan 数据模型已有）。未来接公司内网可控模型端点，把需求清单原文送模型，返回结构化任务树。
  - 一期**不做**，只预留按钮与说明位（与现有 AI Tab 风格一致）。

> 建议：**先落 A1**，把交互链路和数据结构跑通；A2 待你确认模型端点后再接。你若坚持一期就要真 AI，请提供可用的模型端点/鉴权方式。

### 决策 B：需求清单的输入形式
- **B1 粘贴文本**（推荐，最简单）：一个多行 `textarea`，一行一条需求。支持可选前缀编号 `1. / 1.1 / -` 自动识别。
- **B2 上传文件**：`.csv` / `.txt` / `.xlsx`。平台已内置 SheetJS（`xlsx.full.min.js`），可解析 Excel；CSV/txt 直接读。
- 建议 **B1 + B2 都支持**：粘贴为主，上传为辅（上传后填进同一个 textarea 供用户核对再拆解）。

### 决策 C：生成粒度切换
在拆解入口提供一个单选：
- ⚪ **项目总览**（9 阶段一级任务）
- ⚪ **详细计划**（研发计划阶段按需求逐条展开为二级任务）
默认选「详细计划」。

### 决策 D：阶段模板可配置性
9 个阶段先**硬编码为默认模板**（附录给全量）。字段含：阶段名、默认任务类型(type)、默认主责部门(dept)占位、默认交付物(deliverable)。
后续如需按产品线定制模板，再抽到配置文件（本期不做）。

## 3. 交互流程（方案 A1）

```
新建/编辑计划表单
  └─ 「任务 WBS」区块头部，除「＋ 添加任务」外，新增一个次按钮：「⚡ 智能拆解需求清单」
       │
       ▼ 点击弹出拆解面板（SharedUI.confirm 大弹窗 或 二级抽屉）
  ┌─────────────────────────────────────────────┐
  │  智能拆解需求清单 → WBS                       │
  │  粒度：( ) 项目总览   (•) 详细计划            │
  │  需求清单（每行一条）：                        │
  │  ┌───────────────────────────────────────┐  │
  │  │ 1. 支持多语言切换                        │  │
  │  │ 2. 新增设备离线告警推送                  │  │
  │  │ 3. 报表导出 PDF                          │  │
  │  └───────────────────────────────────────┘  │
  │  [ 上传文件(.csv/.txt/.xlsx) ]                │
  │                                               │
  │  [ 取消 ]              [ 生成预览 → ]          │
  └─────────────────────────────────────────────┘
       │ 生成预览
       ▼ 预览生成的任务树（只读表格：阶段/任务名/类型/预估人天占位）
       │  「⟲ 重新生成」   「✓ 采用并填入表单」
       ▼ 采用后 → 任务写入当前 dirtyForm.tasks（父子层级 + parentId 建好），
         用户回到表单继续微调（改人天/负责人/日期），最后统一「保存计划」。
```

要点：
- **不直接落库**：拆解只生成 `dirtyForm.tasks` 草稿，复用现有「保存计划」链路（乐观锁、校验、buildWbsCodes 自动编号）。
- **可叠加/可替换**：预览时提供「替换现有任务」或「追加到现有任务」两种模式（默认替换，若表单已有任务则提示）。
- 生成的任务默认 `status:'not-started'`、`progress:0`、`plannedHours:''`（留空待填）、`type` 按阶段映射。

## 4. 拆解规则（方案 A1 核心算法）

输入：需求清单文本（多行）+ 粒度。
输出：`tasks[]`（含 `id/parentId/name/type/phase/status/priority/plannedHours/dept/deliverable`）。

```
1) 解析需求行：
   - 按换行切分，去空行；
   - 去掉行首编号前缀（正则 /^\s*(\d+(\.\d+)*[.、)]\s*|[-*·]\s*)/）；
   - 每条得到一个「需求标题」。

2) 建 9 个一级任务（阶段），顺序固定（附录模板）：
   需求传递 / 环境准备 / 方案设计 / 技术详设设计 / 测试方案设计 /
   研发计划 / 系统测试 / 实证 / 上市交付

3) 粒度分支：
   - 「项目总览」：只建这 9 个一级任务（parentId 空），不建子任务。
   - 「详细计划」：
       · 「研发计划」一级任务下，为每条需求各建一个二级子任务
         （name = 需求标题，parentId = 研发计划任务 id，type=dev）；
       · 「方案设计 / 技术详设设计 / 测试方案设计」阶段：可选地也按需求各建一条
         （给一个开关：是否把设计/测试阶段也按需求展开，默认只展开「研发计划」）；
       · 其余阶段保留一级任务，给 1 条默认子任务占位（可留空）。

4) 字段填充：
   - type：需求传递=doc、环境准备=ops、方案设计/技术详设=design、
           测试方案设计/系统测试=test、研发计划=dev、实证=ops、上市交付=other；
   - phase：取阶段名；
   - dept/plannedHours/owner/date：留占位（空），交用户在表单里补；
   - deliverable：按阶段给默认交付物文案（附录）。

5) 输出 tasks[]，parentId 关系建好；wbsCode 不在此生成
   （沿用保存时 buildWbsCodes 自动编号，避免和现有逻辑冲突）。
```

## 5. 数据与代码落点（方案 A1）

- **纯前端实现**，不改后端 `routes.js`（tasks 结构、校验都已支持）。
- 新增函数（`modules/plan/index.js`）：
  - `parseRequirementLines(text)` → 需求标题数组；
  - `decomposeToWbs(reqs, granularity, opts)` → tasks[]；
  - `renderDecomposePanel()` + 事件（粘贴/上传/生成预览/采用）；
  - 上传解析复用平台已有 SheetJS（`window.XLSX`）+ 简单 CSV 切分。
- 入口按钮加在「任务 WBS」区块头 `.cs-form-section-head` 里（次按钮，主按钮仍是「＋ 添加任务」）。
- 采用后：`dirtyForm.tasks = 生成结果`（或 concat），`renderFormBody()` 重绘。

工作量评估：**前端约 1 个中等改动**（解析 + 模板 + 预览面板 + 事件），无后端改动，可当天完成并联调。
